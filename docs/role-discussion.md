# 角色与讨论管理设计

版本 1.0.0，配置及角色模板版本 1.0.0。负责人为小组成员 B。依据为《第10组 多智能体任务分解与编排系统设计方案 修订版V2》。旧版 `role-discussion.md` 的角色编号、P3 参与人数及事件名称不作为实现标准。

B 把设计规格中的分解问题组织成有信息差、有证据、有追溯的讨论结果，为 C 的方案生成、D 的评审裁决及 E 的任务整理提供输入。B 不生成正式 WBS，不裁决冲突，不控制状态机，不计算排期。

## 角色和模块的关系

小组成员 A–F 是代码负责人。系统业务角色 A1–A6 是运行时智能体；编排器是 A 模块的代码执行体，不占业务角色编号，也不陈述、不投票。

| 智能体 | 角色 | family | 维护与质疑 | 主要阶段 |
|---|---|---|---|---|
| A1 | 产品经理 | deliberative | 维护交付价值；质疑无来源、越范围任务 | P2、P3、P6；P5 回避 |
| A2 | 用户代表 | deliberative | 维护核心场景；质疑不可感知、不可验收的切法 | P2、P3、P5 |
| A3 | 技术架构师 | deliberative | 维护接口与依赖；质疑成环和无依据估算 | P2、P3、P4、P5 |
| A4 | 质量评审员 | deliberative | 维护风险与验收底线；质疑缺失保障 | P2、P3、P5 |
| A5 | 需求分析师 | processing | 结构化处理与覆盖校验，不持 P3 立场 | P5、P6；低置信度 P2 辅助 |
| A6 | 需求确认员 | processing | 整理确认与基线，不代替人签字 | P7；低置信度 P2 辅助 |

P3 只允许 A1–A4 陈述、质询和投票。P5 的 A2–A5 评分由 D 承接，不能与 P3 投票混为一谈。A1 在 P5 回避，但其 P3 陈述作为历史证据保留，不删除历史。

## 提示词和知识边界

配置在 `src/agents/agent_config.yaml`，模板在 `src/agents/prompt_templates/`。每张角色卡包含角色目标、立场约束、知识边界、上场规则四段。加载时拒绝缺段、非法版本、空质疑义务、可见与禁见冲突，以及引导趋同的指定措辞。

| 角色 | 公共可见 | 独占类别 | 禁见类别 |
|---|---|---|---|
| A1 | spec | business、budget | architecture、risk、user_feedback、acceptance_library |
| A2 | spec | user_feedback | budget、architecture、risk、acceptance_library |
| A3 | spec | architecture | budget、user_feedback、risk、acceptance_library |
| A4 | spec | risk | budget、user_feedback、architecture、acceptance_library |

A5/A6 的处理权限由其本阶段模块决定，不通过 B 的 P3 提示词入口执行。材料目录由宿主明确标注类别、稳定引用和上游规格来源，B 不用模型猜测材料类别。

第一段提示词只包含该角色可见材料和本议题，不包含其他陈述或完整上下文。第二、三段只公开通过校验的主张和问答文本，不分发他人的原始证据材料与证据引用。所有模型返回的 `source_refs` 都必须存在于该角色可见材料集合。

边界校验能阻止非法证据引用，但无法保证自然语言主张绝不复述敏感信息。模板要求独占证据只作概括；含敏感资料的正式使用仍应由 A 做材料脱敏，并由 D 审查公开主张。

每次讨论记录配置和模板的 SHA-256 指纹。同一轮后续步骤发现内容变更即拒绝，防止运行中热替换。跨运行变更应更新版本，并同步本文件。

## P2 召集

A 提供规范化设计规格与分类结果，B 的 `build_convocation` 生成召集表和角色卡快照。分类允许多标签：functional、technical、cost、risk，分别关联用户、技术、产品、质量视角。A1 作为模块责任组织者参加，A3 和 A4 无条件参加。

默认置信度阈值是 0.75，这是本实现可调参数，修订版没有规定该数值。低于阈值时全员 A1–A6 召集；A5/A6 作为处理型角色辅助，不因此获得 P3 投票权。缺分类或非法置信度时报错，不擅自猜测。

B 不做 P2 分类模型调用、不生成正式 module_map；这些由 A 的分类器与 A1 承接。

## P3 三段式协议

议题词表只有四类：granularity 拆分粒度、dependency 依赖方向、estimate 工时依据、acceptance 验收口径。别名在配置中维护；A/D 应按稳定 topic_id 对接。新增词表项必须先统一配置及契约，不能让模型自由创造。

### 独立陈述

每次 `run_discussion` 只执行一个议题、一个步骤。第一步为 A1–A4 创建独立请求，最多三个工作线程；四个提示词在调用前固定，不因先返回者的结果改变。修订版并行度上限为 3，因此四角色互不可见地提交，但不会同时发出四个网络请求。

输出记录 position、claim、source_refs、稳定记录 ID 和角色 ID。FOR/AGAINST 始终指向同一议题命题，NEUTRAL 允许表达信息不足。立场与事实正确性由 D 判断，不能为制造异质性强迫反对。

### 防趋同

代码计算两种相似度：embedding 向量余弦和去空白标点后的字符 bigram 集合 Jaccard。语义分数达到 0.85，或字面分数达到 0.70，即触发补发言，使用“或”关系。

为保证并发重放确定性，保留 A1→A4 顺序中先被接受的陈述，让后者补发言；本地顺序不冒充真实提交时间。补发言最多两次，必须引用至少一条自身独占证据，且与上次文本的语义相似度低于 0.6。embedding 不可用时按字面低于 0.6 作降级判断，并公开降级状态，不能称为已通过语义校验。两次后仍趋同则挂起，输出 `E_GROUPTHINK`，交 A 决定换角度重开。

embedding 缺失、异常、零向量、维度不符或非有限值均降级；语义分数记录为 null，字面检测继续执行，并发出 `guard.signal`。

### 定向质询

独立陈述结束后，B 输出冲突候选引用，D 据此登记正式 `conflict_register`。A 将登记产物传回 B，再执行 query。因此冲突是在质询前登记，不是讨论完后补记。

质询只面向同一议题的 FOR/AGAINST 对立立场，必须指向具体角色、原陈述与正式冲突号。B 的主持模板直接引用被质询者的公开主张，要求说明适用条件、代价和验证依据，由对方模型回答；不额外消耗提问模型调用。每个被质询角色在本步最多回答一次，多个冲突下的其他问题由 A/D 在后续轮次明确提出。

空回答和无效证据触发一次修正。自然语言是否答非所问、证据是否足以支持观点，交 D 审查；B 不用字符串匹配冒充语义判断。需要补充讨论时由 A 按 D 意见组织下一轮。

### 结构化投票

A1–A4 各一票，FOR、AGAINST、ABSTAIN 三种票型；必须有理由和有效证据引用。无理由弃权同样无效，允许一次修正。B 原样计数，不做 D 的角色加权、不输出胜方。少于三张有效票为本实现的保守门槛，挂起并交 A/D 处理；平票标为 CONTROVERSIAL，交 D 按修订版三级裁决。

P3 最多三轮。每轮开始用新的陈述输入，不将上一轮的角色意见夹带进独立陈述；A 可在新议题命题或本轮明确材料中广播已确认的新约束。历史轮次由 A 归档，不覆盖事件。是否达到出口闸门、是否转人工均由 A/D 判断，B 不更改全局状态。

## 用户价值与任务粒度

`evaluate_user_value` 只给建议，不修改任务或排期。输入来源必须能解析为 design_spec 中的 FEA/CON。标记由人或已确认的上游产物明确给出，B 不推测：

| 明确依据 | 建议 priority |
|---|---|
| 本期范围外 | W |
| 强制约束或核心用户流程 | M |
| 明确高用户价值 | S |
| 明确低用户价值 | C |
| 价值信息不足 | null，并要求确认 |

技术前置任务可以通过约束来源获得 M，不以“用户看不到”判为无价值。M 代表应优先纳入交付，不代表可以越过依赖立即开工。依赖、资源与具体起止时间由 A 决定。

超过 3 人天的任务给出拆分提醒；缺验收记录提示。B 不取代 D/E 的正式闸门校验，也不生成 P6 正式任务卡。

## 异常和预算

| 情况 | B 的处理 |
|---|---|
| 缺输入、跨 run_id、错误 schema_version | 抛 AgentError，不猜测补齐 |
| 错误步骤顺序、重复同一步 | 拒绝执行，避免重复投票 |
| 格式错误或越界证据 | 本步骤最多一次修正，仍失败按缺席处理 |
| 真实调用超时 | 记 E_AGENT_UNAVAILABLE，不扣调用预算；其他角色继续 |
| 供应商异常 | 记 E_MODEL_UNAVAILABLE；返回已观察到的调用费用，保守计一次 |
| 分配预算不足 | 不继续调用，发 E_BUDGET_LIMIT，输出已有结果 |
| 多次趋同 | 挂起议题，不私自跳到下一阶段 |
| 平票或有效票不足 | 给出信号，交 A/D 处理 |

正常一轮四次陈述、最多四次回答、四次投票，共十二次。重试也计费，可能挤占后续步骤预算；不能为了完成投票突破预算。传入的 budget_left 必须是 A 计算后的“全局剩余与 P3 阶段剩余额度的较小值”。本模块限制调用次数，但不重建全局账本。

真实 HTTP 适配器落实 120 秒传输超时；外部注入回调也必须遵守 timeout。Python 无法安全强杀不遵守契约的第三方线程，宿主若要隔离任意不可信回调，应使用进程或独立模型服务。

## 对外边界与验收

所有模块函数返回 StageResult；不写 runs、不修改输入、不调用其他模块。事件仅返回类型和 payload，不赋全局 seq；A 负责落盘、计费、发布事件和状态变迁。独立 CLI 是演示宿主，文件写入与模拟序号分配发生在 CLI，而不是模块接口中。

实际接口示例、联调顺序及验收范围见 `src/agents/README.md`。自动测试覆盖隐私视图隔离、对立质询、无理由弃权、预算、超时、模型格式错误、重复发言、embedding 降级、上下文不变性与价值来源等。固定样例可在 `src/agents/examples/expected/` 检查。
